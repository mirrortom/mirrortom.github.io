AES-GCM加密方案

作者: mirror 日期: 2026/07/03

更新2026/07/06

加密解密是常用到的功能,需要正确使用以保证效果.本文记录一下AES方案的关键内容.

概述

AES全称是高级加密标准,Advanced Encryption Standard.但怎么高级了呢,这个没研究.可能是因为比之前的DES加密方案要高级.但这就是个加密方案的名字而已,历史上经过多个版本改进.

AES自2001年正式由美国发布以来,经历了很多版本,早期的做法是块加密(Block Cipher),就是将明文数据分成大小固定的若干小块,比如每块128bit,如果最后不够还要填充,然后对每块加密,最后得到密文.这个办法缺陷是如果明文块相同,那么密文也相同,容易被统计分析,这是不足之处.

AES-GCM

GCM方案是叫做认证加密.实际上做了2个工作,加密和效验(Galois/Counter Mode).这是目前业界推荐的方案.

1. Galois(伽罗瓦)是认证算法,类似于做hash,得到一个指纹,如果数据被改过了,指纹就对不上.使用aes-gcm加密后,得到一个tag参数,是一个指定长度的字节,将来解密时,要传入这个tag,如果数据被改,解密会停止.

2. Counter是加密算法,计数器模式(Counter Mode)加密算法.它的做法是,根据一个随机数(Number used once),加上计数器(Counter),生成一个128bit的块,再用aes密钥加密这个块,得到128bit的密钥块,然后和明文XOR运算,结果就是密文了.这样,第一次XOR后,得到128bit的密文.重复这个过程,Counter累加,生成新的128bit块再加密得到密文.一直到最后XOR完所有明文,就得到了全部密文.可以想象,XOR运算时,不需要先将明文分块,最后的明文长度不够128bit时,取明文长度的XOR结果就可以了.

加密过程

Pbkdf2密钥生成

AES密钥是关键参数,密钥位数是16/24/32字节,长度是128/192/256 bits,越长越安全,算力耗费也越多,16/128的效果不错了,极其严格的场合用32/256的,这是查阅到的建议.本文使用16/128长度的.

如何搞到16/128密钥,可以随机填充一个16字节数组,可以手动凑齐16字节,但可靠的办法是使用密钥生成器.例如:Pbkdf2,全称是(Password-Based Key Derivation Function 2).翻译下就是,基于密码的密钥衍生函数二.简单的说就是给一个密码,生成一个AES密钥.

// c#的该函数
key = Rfc2898DeriveBytes.Pbkdf2
    (pwd, salt, iterations, hashAlgorithm, outputLength)
参数说明
pwd密码,用户提供的.根据建议,密码字符不少于8个,且要含有数字/字母/特别符号组合.
salt盐.本文使用16字节长度.
iterations迭代次数,越多耗时越长,破解难度越大,查阅到的建议有6万次,10万次,60万次(2024年推荐),根据CPU算力的增强而增加.本文使用10万次.
hashAlgorithm哈希算法,本文使用SHA256.参数作用没研究.
outputLength密钥长度,生成的密钥长度.应为16/24/32,本文使用16.

salt盐的作用是,相同密码加上不同盐,产生的密钥不同.这样干可以防止查表反推密码.通常情况下,服务器不保存用户密码,而是做hash后存放这个结果.那么就可以事先造出很多密码,再做hash,就得到一个对照表,对比服务器密码表后,如果发现hash相同,那么就查到了密码,不过前提是没有加盐.同一个密码,如果加了一个随机数,再做hash,结果会不同,这个盐就是起这个作用的.

// 随机一个盐值
salt = RandomNumberGenerator.GetBytes(16);

AesGcm.Encrypt

有了密钥就可以加密了,使用AesGcm类的实例方法.

// 实例化
using var aes = new AesGcm(key, TagSize)
// 加密
aes.Encrypt(nonce, plaintext, ciphertext, tag);
参数说明
key密钥
TagSize认证值长度.检查加密是否被该过的特征值的长度.建议是12/16,本文用16.
nonce随机数,用于计数器模式算法产生密钥块.
plaintext明文数据
ciphertext密文字节数组容器.长度和明文数据等长.
tag认证值字节数组容器

nonce是关键参数,Number used once,翻译就是,数字使用一次.按照文献说法,同一个密钥绝对不能使用相同的nonce,否则能直接破解出明文数据.从名字上看也比较清楚,就是只能用一次的.本文使用12长度.

// 随机生成nonce
nonce = RandomNumberGenerator.GetBytes(12);

ciphertext参数,一个空数组,加密执行后会填充.密文数据和明文数据是等长的,这一点经过测试,33个字节的数据加密后的密文也是33字节.

结果保存

加密后得到的结果,除了密文,还有tag.另外,加密用到的salt/nonce也要保存,否则无法解密.根据查阅的资料建议,做法如下:

1.不要保留密钥,解密时重新生成密钥.因为如果密钥存下了,如果密钥被盗就会泄密,不需要原始密码了.

2.使用格式例如 [salt][nonce][tag][cipher] 保存结果.解密时,分段取出,然后重新生成密钥,再解密.

本文使用格式是,盐(16) + nonce(12) + tag(16) + [cipher],然后转为base64字符串存放.

解密过程

密钥重新生成

分析加密密文,对照结构,取出salt值,执行Pbkdf2方法再次得到密钥.注意其它参数必须和加密时生成密钥输入的参数相同,iterations(迭代次数),hashAlgorithm(哈希算法),outputLength(密钥长度).

AesGcm.Decrypt

取出nonce/tag/cipher参数,执行解密方法.plaintext就是解密结果.

// 实例化
using var aes = new AesGcm(key, TagSize);
// 执行解密
aes.Decrypt(nonce, ciphertext, tag, plaintext);

注意事项

用户密码不存服务器,加盐后计算hash存放,算法md5或者sha128/256.

密钥不留存,加密解密都要重新计算.

nonce/salt必须使用随机数生成器,严禁重用.

使用场景

用于客户端加密,用户在APP上使用AES加密数据,密钥自己管理.加密数据存在服务器上,比如云盘.使用时,下载加密数据,在客户端上解密数据.加解密都是在客户端的,服务器只是保存数据.

浏览器/WEB服务器应用,不适合用AES,可以使用公钥私钥方案.
